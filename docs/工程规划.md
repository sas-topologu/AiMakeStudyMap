# 智点星谱 · 工程规划

> 版本：v1.0　依据：`zxt.txt` 项目综述　状态：已批准执行

## 1. 项目定位

公益向知识图谱学习平台：知识如「山」（前后依赖形成攀登路线）、如「网」（相关性连接形成体系）。前端以星图呈现：节点为星、连线成图；类游戏闯关驱动学习，类贴吧社区沉淀讨论与二创。

- 开发模式：AI 为主力开发，人类辅助审核
- 维护模式：模块化设计，适配 AI 后期维护与内容迭代
- 内容边界：本工程**不包含正式知识卡内容制作**；内容管线（规范、校验、导入、审核）由工程提供

## 2. 总体架构

前后端分离，支持多平台个人端。首个个人端为 Web 响应式（桌面/手机浏览器通用）。

```
┌─────────────┐   HTTP/JSON (JWT)   ┌──────────────┐
│  Web 个人端  │ ◄────────────────► │  Node.js API  │
│ Vue3+Canvas │                     │   Express     │
└─────────────┘                     └──────┬───────┘
                                           │ better-sqlite3
                                    ┌──────▼───────┐
                                    │   SQLite     │
                                    │ 节点库+用户库 │
                                    └──────▲───────┘
                                           │ 导入/校验/结构检测
                                    ┌──────┴───────┐
                                    │ content/     │
                                    │ 知识卡 JSON  │
                                    └──────────────┘
```

三库设计对应原文：

- **节点数据库**（静态、高可信度、版本化）：知识节点内容、关联关系、题库、版本号；经审核后入库
- **用户数据库**（动态、高频读写）：用户进度（节点状态）、跃迁额度、社交数据、个人设置；**核心状态判定全部在服务内核校验**
- **本地缓存**（个人端）：临近节点数据；基于版本号校验，联网比对后拉取差异更新

## 3. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Node.js 20+ / Express / better-sqlite3 / JWT / zod | 单语言全栈、SQLite 零依赖部署、参数校验严格 |
| 前端 | Vue 3 + Vite + Pinia + Vue Router | 响应式 Web，生态成熟 |
| 星图渲染 | 自研 Canvas 2D 渲染器（LOD 分层） | 星云/星团聚合效果与海量节点性能需完全掌控 |
| 内容 | JSON 知识卡 + 校验/导入 CLI | AI 可读写、可版本化、可 diff 审核 |
| 测试 | Vitest | 与 Vite 同栈 |
| 部署 | 单命令启动，服务内核托管个人端构建产物 | 本机/局域网/公网均可 |

## 5. 分期实施计划

> 每阶段完成并验证后进入下一阶段。

### 阶段 0：脚手架与工程规划 ✅
monorepo 初始化、本文档。

### 阶段 1：数据层与内容管线
- 知识卡 JSON Schema：节点内容、关联（前置/后续/相关）、题库、难度、可信度、版本号
- SQLite 表结构：节点库 + 用户库
- 结构检测：前置依赖死循环检测（DAG 校验）、孤岛节点/节点群检测
- 导入工具：校验 → 结构检测 → 入库 → 版本迭代
- 示例数据：10~20 个数学/物理演示节点（一条可闯关学习路径）

### 阶段 2：后端核心 API
- 认证（注册/登录/JWT）
- 星图分层查询（深度 ≤2，不拉全库）
- 节点状态机（服务内核校验）：暗淡 → 开放 → 通关 → 点亮，权限按状态收紧
- 闯关与考核：试卷生成（通关 3 题；点亮全量、上限 20、难度高题数少）、自洽性校验
- 跃迁：模糊匹配；封闭节点耗 1 额度转开放（月赠 1、上限 2、不足拦截）
- 时间管理：闯关前必开倒计时（不可取消、到时强制退出）；防沉迷日上限 2 小时
- 版本同步：版本号比对 + 差异更新

### 阶段 3：前端核心（中心视图 + 学习闭环）
- Canvas 中心视图：当前节点居中；对角线四象限（前置下、后续上、相关两侧）；深度 2 层；防碰撞布局；相关线过多可折叠
- 四态亮度渲染 + 可信度颜色（绿-验证通过 / 黄-存在争议）
- 知识卡页：闯关按钮、计时器、试卷答题流
- 夹层系统：专业名词/参数/算子点击弹悬浮定义，多级嵌套
- 跃迁与搜索 UI

### 阶段 4：宏观视图（大地图）
- 宇宙视图（学科星系聚合发光、星云效果）→ 点击进入星座视图
- 星座视图：地图引擎式缩放平移；星团聚合 → 放大解体为离散节点网络；主干路径星座连线；可逆向
- LOD 分层聚合保证海量数据不卡顿

### 阶段 5：导航系统
- 流程：关键词 → 模糊匹配 → 选目标 → 选路线类型 → 高亮渲染
- 最短路径（仅核心前置）/ 全面路径（含相关拓展）/ 低难路径（绕开高难节点：通关人数少为高难，仍显示但标注）
- 热门路径：高通过率路径高亮（可选开启）

### 阶段 6：社交系统
- 分级讨论区（类贴吧）：节点讨论板；每小时发帖 >100 自动限流
- 二创区：通关用户上传（思维导图/小游戏/总结图），审核后展示
- 前十纪念碑：点亮时该节点点亮人数 <10 且半小时后仍 <10 → 永久「拓荒者」标记 + 永久置顶留言
- 速通榜：节点级点亮耗时排行；高排名用户发言标记并提高推送概率
- 星图分享：已通关节点导出星座图分享，支持滤镜/折叠自定义

### 阶段 7：维护与审核工具
- 勘误流程：用户提交 → 待办任务 → 审核 → 合并主库 → 版本迭代
- 待审核队列（AI 内容 / 二创 / 勘误共用审核流）+ 更新日志
- 孤岛/空洞节点扫描工具（供 AI 维护流程调用）

### 阶段 8：文档与收尾
- 《知识卡制作规范》《维护手册》《部署运行指南》
- 全量回归测试与构建验证

## 6. 核心设计决策

1. **状态判定全部在服务内核**：节点状态流转、跃迁扣额、计时与防沉迷均由服务内核校验，个人端只做展示
2. **题库随卡入库**：题目作为知识卡一部分静态存储，试卷在服务内核按规则抽题；难度高 → 题数少（上限 20），通关时耗建议 ≤40 分钟
3. **坐标为逻辑拓扑**：星图坐标由布局算法按拓扑生成，不遵循物理空间，优先逻辑清晰
4. **渲染深度限制**：中心视图连线延伸 ≤2 层（A→B→C）；前端渲染限制无限递归
5. **高难节点判定**：以「通关人数少」为信号（阈值可配置，默认通关人数 <10 且尝试人数 ≥20 判为高难）
6. **版本同步**：节点库单调递增版本号 + 每节点版本；个人端上报本地版本，服务内核返回差异

## 7. 验证标准

- 后端 Vitest 全绿（状态机 / 寻路三算法 / 循环与孤岛检测 / 跃迁额度 / 限流 / API 集成）
- 前端 `vite build` 通过；示例数据冒烟：注册 → 浏览 → 闯关 → 点亮 → 跃迁 → 宏观视图 → 发帖/二创 → 分享
- 《部署运行指南》步骤实跑可复现
