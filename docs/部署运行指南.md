# AI点星谱 · 部署与运行指南

> 版本 v1.0。本指南步骤经过实际运行验证。按顺序执行即可完成从裸机到可用系统的全部部署。

## 1. 环境要求

- **Node.js ≥ 20**（开发验证版本 v24；含 npm）。安装： https://nodejs.org/
- 操作系统：Windows / macOS / Linux 均可
- 磁盘：约 300MB（含依赖）；运行内存：512MB 以上
- 无需安装任何数据库——系统使用内嵌 SQLite（单文件）

## 2. 首次部署

在项目根目录（本文件上一级目录）执行：

```bash
# 1. 安装依赖
npm install

# 2. 一键部署 = 构建前端 + 导入知识卡 + 启动服务
npm run deploy
```

启动成功后访问：

- 应用入口：`http://localhost:3000/`（局域网/公网部署用对应主机地址）
- 健康检查：`http://localhost:3000/api/health` 应返回 `{"ok":true,...}`
- 更新日志：`http://localhost:3000/changelog`

**第一个注册的账号自动成为管理员**（可访问 `/admin` 审核队列）。请首先注册管理员账号。

### 分步形式（排障时用）

```bash
npm run build     # 构建前端到 web/dist/
npm run import    # 导入 content/cards/ 全部知识卡 → server/data/starmap.db，迭代内容版本
npm start         # 启动服务（node server/src/index.js）
```

### Windows 依赖安装故障处理

若 `npm install` 因 better-sqlite3 编译失败（本机无 Visual Studio 构建工具），执行：

```bash
npm install --ignore-scripts
cd node_modules/better-sqlite3
npx prebuild-install --mirror https://registry.npmmirror.com/-/binary/better-sqlite3
cd ../..
```

Linux/macOS 一般会自动命中官方预编译包，无需此步骤。

## 3. 生产环境配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `STARMAP_SECRET` | `dev-secret` | **JWT 签名密钥，生产必须覆盖**为足够长的随机串 |
| `PORT` | `3000` | 监听端口 |
| `STARMAP_DB` | `server/data/starmap.db` | SQLite 数据库文件路径 |

Windows（Git Bash）示例：

```bash
export STARMAP_SECRET="$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")"
export PORT=8080
npm start
```

Windows CMD：`set STARMAP_SECRET=...`；PowerShell：`$env:STARMAP_SECRET="..."`。

## 4. 局域网 / 公网访问

- 服务默认监听所有网卡，局域网内直接访问 `http://<本机IP>:<PORT>/`。
- 前端为 history 模式 SPA，**已由后端统一托管并处理路由回退**（`/share/:id`、`/changelog` 等路径直接访问会正确返回应用）——不要用其他静态服务器单独托管 `web/dist`，除非你自行配置回退规则。
- 公网部署建议：置于 Nginx/Caddy 反向代理之后并启用 HTTPS，反代时把整个站点（含 `/api`）转发到 `127.0.0.1:<PORT>` 即可，无需分流。
- 防火墙需放行所选端口。

## 5. 日常使用与内容更新

### 5.1 后台运行

```bash
# Linux/macOS
nohup npm start > starmap.log 2>&1 &
# 或使用 pm2 / systemd

# Windows：直接保持终端窗口，或用 pm2-windows-service / NSSM 注册为服务
```

### 5.2 更新知识内容（标准流程）

1. 新卡/改卡放入 `content/staging/`，校验：
   ```bash
   node content/tools/import.js --dir content/staging --check --with-db server/data/starmap.db
   ```
2. 审核通过后移入 `content/cards/`，执行：
   ```bash
   npm run import
   ```
   服务**无需重启**；内容版本自动 +1 并记录更新日志，在线用户下次同步自动收到差异更新（前端会提示"知识库已更新"）。

详细规范见《知识卡制作规范》，勘误/二创审核见《维护手册》。

### 5.3 维护扫描

```bash
npm run scan     # 孤岛/空洞节点、待办积压、结构健康、版本信息
```

### 5.4 运行测试

```bash
npm test              # 后端 63 用例
npm test -w web       # 前端 36 用例
```

## 6. 备份与恢复

- **备份**：只需复制一个文件 `server/data/starmap.db`（含全部内容与用户数据）。建议停机复制，或在线复制前先执行 checkpoint：
  ```bash
  node -e "require('better-sqlite3')('server/data/starmap.db').pragma('wal_checkpoint(TRUNCATE)')"
  ```
  `content/cards/` 源卡与 `content/assets/` 图片资产是内容的事实来源，应与数据库一起纳入版本管理/备份。
- **恢复**：停止服务 → 用备份文件替换 `server/data/starmap.db` → 重新启动。
- **重置为初始状态**：停止服务 → 删除 `server/data/starmap.db` → `npm run import && npm start`（用户数据将清空，内容恢复为 cards 源文件状态）。

## 7. 升级系统（代码更新）

```bash
# 拉取新代码后
npm install          # 依赖有变化时
npm run build        # 重建前端
npm test             # 建议先跑通
npm start            # 重启服务；数据库迁移（migration）会在启动时自动应用
```

数据库结构升级全自动（`schema_migrations` 表记录已应用版本），无需手工干预。

## 8. 常见问题（FAQ)

**Q：启动后访问 `/` 提示"前端尚未构建"？**
A：未执行 `npm run build`，或启动目录不是项目根。执行 `npm run build` 后重启。

**Q：登录后一会儿就掉线？**
A：JWT 有效期 7 天，属正常；若频繁 401，检查服务器与客户机时间是否同步、是否更换了 `STARMAP_SECRET`（更换后所有旧 token 失效）。

**Q：用户反馈"今日计时已达上限"？**
A：防沉迷规则，每人每日闯关计时累计 120 分钟，次日自动恢复。其他功能不受影响。

**Q：跃迁提示额度不足？**
A：规则为每月赠 1 点、存储上限 2 点，只能等下月发放或让目标节点通过正常通关解锁相邻来开放。

**Q：管理员是谁？如何添加？**
A：第一个注册的账号自动成为管理员。追加管理员：`node -e "require('better-sqlite3')('server/data/starmap.db').prepare(\"UPDATE users SET is_admin=1 WHERE username=?\").run('用户名')"`。

**Q：如何修改讨论区限流阈值？**
A：`meta` 表 `post_rate_threshold`（默认 100/小时/节点），改后立即生效，见《维护手册》§3。

**Q：端口被占用？**
A：换端口：`PORT=8080 npm start`。

**Q：数据库文件可以删吗？**
A：可以，但等于清空全部用户与进度数据。内容数据可经 `npm run import` 重建，用户数据不可恢复——删前确认已备份。
