# 智点星谱 · 客户端与终端

> **定位**：一个**工具** —— 单机即可全功能；云端是**可选**的「数据仓库 + 社区」。

## 一、两个部件（同仓库两个目录）

| 目录 | 部件 | 是什么 |
|---|---|---|
| `server/` | **终端** | 数据与社区服务：知识库、账号、学习进度、投稿/审核、讨论/二创、举报。装在哪台机器，哪台就是"终端"。 |
| `web/` | **客户端** | 界面工具：星图、知识卡、闯关、管理。可指向任意终端。 |
| `content/` | 知识卡内容 | 知识卡 JSON 与制卡/校验工具。 |

- **单机全功能**：本机同时跑「终端 + 客户端」，全部功能可用（无需联网）。
- **云端**：把终端部署到服务器（如 `https://aimakestudymap.online`），作为**数据仓库**（最新知识库）与**社区**（多人）。

## 二、三种运行方式

### 1. 单机（推荐个人使用）
```bash
npm install
npm run build          # 构建客户端
npm run import         # 知识库入库（仓库里有多少卡就导入多少）
npm start              # 启动终端（默认 3000）
```
浏览器打开 `http://localhost:3000` → **单机模式**：社区类功能自动不可用。

### 2. 云端（作为数据仓库 + 社区）
部署到服务器（见 `docs/上线部署指南.md`），客户端通过域名访问 → **云端模式**：社区功能可用。

### 3. 客户端指向其它终端
客户端「设置 → 终端」里可填写并切换到别的终端地址（记住历史），切换后重新加载。
- 默认指向**本地终端**（当前页面地址 / 构建时注入的 `VITE_TERMINAL_URL`）
- 单机模式下无法使用社区/分享功能（那些依赖云端多人环境）

## 三、管理员（两级）

| 级别 | 怎么来 | 能做什么 |
|---|---|---|
| **终端管理员**（owner） | **在终端本机登录后认领**（设置 → 认领为终端管理员）；仅本机请求可认领 | 完全权限：设置/轮换**授权密钥**、管理终端、审核、投稿、举报 |
| **二级管理员** | 持有 owner 发放的**授权密钥**，登录后提交（注册页或登录后）| 审核投稿/勘误/举报、管理面板；**不能**设置授权密钥、不能管终端 |
| 普通用户 | 直接注册 | 学习、闯关、发帖、投稿（经审核） |

- owner 在「设置 → 管理员」里**生成授权密钥**，发给他人 → 对方即成为二级管理员。
- 云端部署时，owner 可在服务器上对本机发起认领（`POST /api/auth/claim-owner`，仅 loopback 允许）。

## 四、知识库来源（都可选，不强制）

工具**不依赖内置知识库**，空库也能正常使用。补充知识卡的三种方式：
1. **AI 制作**：走 `/api/agent/spec`（规范+模板）→ `/api/agent/cards` 投稿 → 审核通过入库。
2. **自有 JSON**：放进 `content/cards/`，运行 `npm run import`。
3. **从云端终端拉取**（可选）：
   ```bash
   npm run pull-cards -- https://aimakestudymap.online
   npm run import
   ```

## 五、数据与安全

- 终端数据库：`server/data/starmap.db`（SQLite），**不入版本库**。
- 客户端与终端的通信：HTTP(S) API；云端终端配 HTTPS 证书 → 客户端连它时可校验身份（防仿冒）。
- 服务端**不主动读取**用户内容；仅在用户显式触发（投稿/举报/@AI）时经任务桥处理。
- 密钥：`STARMAP_SECRET`（鉴权签名）、`STARMAP_ADMIN_KEY`（终端引导密钥，可选）。

## 六、可关闭模块

「设置 → 功能模块」可关闭：导航 / 社区 / AI 助手 / 分享星图 / 计时 / 流星 / 星光粒子。
- 单机模式下，**社区**、**分享星图**自动不可用（与开关联动）。

## 七、风险防护

### 1. 服务器可能不在（离线容错）
- **熔断**：请求失败即进入**离线态**，在冷却期（30 秒）内**快速失败、不再发起网络请求**，避免反复申请空转占用资源；冷却后自动尝试恢复一次。
- **本地兜底**：离线时星图/知识卡使用浏览器本地缓存（`starmap.cache.v2`）继续渲染；初始中心退化为缓存的任一节点。工具本身不依赖终端在线。
- **提示**：顶部出现「终端暂时不可达」提示条，可点「立即重试」手动恢复。
- 客户端内**没有**对终端的轮询（计时器只在本地倒数），不会持续占用网络与 CPU。

### 2. 域名丢失 / 被他人夺走（防仿冒）
- 每个终端有**持久化的身份指纹**（首次运行生成，存于数据库；`GET /api/terminal/info` 返回）。
- 客户端**首次连接时记住该指纹**（TOFU）；之后若指纹不同 → 说明"不是原来的终端"（例如域名被他人接管、换了一台服务器），顶部出现**红色警示**并暂停自动信任，需用户明确确认或切回默认终端。
- 注意：**HTTPS 证书不足以防这种替换**（新域名持有者也能申请合法证书），因此需要指纹校验。

### 3. 信息通道：**上行（上传）与下行（下载）都受限，且格式可配置**

**下行（终端 → 客户端，下载通道）**
- **前端外壳**：只允许前端运行所需格式（`html/js/css/json/svg/png/jpg/gif/webp/ico/字体/txt/webmanifest`）；
  其他扩展名（如 `.exe`、`.zip`）一律 `404` —— 站点**不会被当作任意文件分发通道**。
- **用户内容**（图片/附件）：`/api/assets/*` 按**可配置白名单**放行，带防目录穿越。
- 所有响应带 `X-Content-Type-Options: nosniff`（防止浏览器按内容嗅探类型、把文件当可执行内容）；SVG 另附 CSP 禁脚本。

**上行（客户端 → 终端，上传通道）**
- 接口只接受 `application/json`（其余返回 `415`）；**文件以 base64 放进 JSON** 传输，通道保持统一。
- `POST /api/upload`（需登录）限 5MB，落盘 `content/assets/uploads/`，返回站内 URL；评论区可「🖼 插入图片」。

**格式白名单可配置（不写死）**
- 终端管理员在「设置 → 管理员 → 允许的文件格式」维护（逗号分隔）。
- 默认：`png / jpg / jpeg / gif / webp / svg / pdf / txt / md / csv / json`。
- 说明：用户内容的白名单**可配置**；前端外壳的格式是构建产物、固定为安全集合。

> ⚠️ 诚实说明：如果客户端是**由终端页面提供**的，那么"域名被夺"者也能替换前端代码——此时任何前端校验都可能被绕过。
> 真正的防护是**从可信来源获取客户端**：本地运行（单机）或从 GitHub 安装；再用指纹校验终端身份。这也是"工具（单机全功能）"的定位价值。

### 4. 身份指纹与去中心化数据分布**互不影响**
- 指纹只是"终端身份证"，用于客户端判断"是不是我信任的那台终端"；**知识卡是纯 JSON、不带终端绑定**，可自由在终端之间传递（`pull-cards`）。
- 客户端按**每个终端地址分别记住指纹**，指向任意终端互不干扰。
