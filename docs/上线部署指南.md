# 智点星谱 · 上线部署指南

> 面向"会使用 GitHub、非专业运维"的你。本指南用 **VPS 服务器 + GitHub 拉取部署**。
> 为什么不用云托管（Render/Railway 免费层）：本项目数据在 **SQLite 文件**，云平台免费层磁盘是临时的、不持久，**重启/重新部署会丢数据**；VPS 磁盘永久才适合。

配套文件（本仓库 `tools/deploy/`）：`ecosystem.config.js`(PM2)、`nginx-starmap.conf`(反向代理)、`backup.sh`(每日备份)、`create-admin.mjs`(建管理员)、`deploy.sh`(一键更新)、根目录 `.env.example`。

---

## 一、把代码放到 GitHub

1. 在 GitHub 新建一个私有仓库（如 `starmap`）。
2. 本仓库已 git 初始化；添加远端并推送：
   ```bash
   git remote add origin 你的GitHub仓库地址
   git push -u origin main
   ```
3. ⚠️ 确认 `.gitignore` 已忽略 `server/data/`（数据库、密钥不入库）、`node_modules/`、`.env`。`server/data/starmap.db` 是构建产物+本地数据，**不要提交**。

## 二、买服务器 + 装环境

**一台 VPS**（腾讯云/阿里云/华为云/DigitalOcean…，最低配即可）。系统选 **Ubuntu 22.04**。记录服务器 **IP** 和 **root 密码**。

SSH 登录（Windows 命令提示符或 PowerShell）：
```bash
ssh root@你的服务器IP
```

装 Node 20 + 工具：
```bash
apt update && apt install -y git curl
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v   # ≥ 18 即可
```

## 三、拉代码 + 部署

```bash
cd /root
git clone 你的GitHub仓库地址 starmap
cd starmap
```

**首次部署**（手动，或用 deploy 脚本）：
```bash
npm install
npm run build        # 生成 web/dist（前端构建产物，静态托管用）
npm run import       # 内容入库 → server/data/starmap.db
```

> 前端是构建产物 `web/dist`，由后端静态托管。以后每次更新用 `tools/deploy/deploy.sh` 即可（pull+build+import+restart 一条龙）。

## 四、⚠️ 建立管理员（用密钥，防抢注）

代码已**取消"首个注册自动成为管理员"**——管理员只能通过**管理员密钥**开启。

**第一步：在启动/PM2 环境里设置密钥**（与 `STARMAP_SECRET` 一起）：
```bash
export STARMAP_ADMIN_KEY=$(openssl rand -hex 32)
```

**第二步：用密钥注册成管理员**（任选其一）：
- **A（推荐）**：在注册页"管理员密钥"一栏填上该密钥，注册即成为管理员。
- **B**：先注册成普通用户，登录后在站内提交管理员密钥开启（`POST /api/auth/promote-admin`）。
- **C（备选）**：直接在服务器用脚本建管理员（不依赖密钥）：`node tools/deploy/create-admin.mjs 你的管理员名 '强密码Xx12345' 你@邮箱.com`

之后陌生人注册只能是普通用户，无法成为管理员。

## 五、启动（保活）+ HTTPS

**PM2 保活**（服务常驻、开机自启）：
```bash
npm install -g pm2
export STARMAP_SECRET=$(openssl rand -hex 32)   # 生产必须设强密钥，别留 dev-secret
pm2 start server/src/index.js --name starmap
pm2 save && pm2 startup   # 按输出的一条命令执行一次
pm2 status                 # 应显示 online
```

**Nginx 反向代理 + HTTPS**：
```bash
apt install -y nginx
sudo tee /etc/nginx/sites-available/starmap < tools/deploy/nginx-starmap.conf
# 编辑把 "你的域名" 改成你的域名
ln -s /etc/nginx/sites-available/starmap /etc/nginx/sites-enabled/starmap
nginx -t && systemctl reload nginx

apt install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名   # 自动配 SSL + 自动续期证书
```

## 六、上线自检

```bash
curl http://127.0.0.1:3000/api/health     # 应返回 {"ok":true,"contentVersion":53}
```
浏览器打开 `https://你的域名`：**公网只会看到「群体端说明页」**（群体端不对外提供学习界面），这是正常的。
- 管理请打开 `https://你的域名/admin`（库管理界面）：登录 → 库概览 / 待处理任务 / 补认证
- 学习界面在**个人端**：PC 个人端 / 手机个人端（在其「设置 → 数据源」里指向 `https://你的域名`）
- 投稿一张卡，看是否进入"待审" → 管理 AI 一审

> 本机（服务器上 `curl http://127.0.0.1:3000`）访问根路径才会加载学习界面 —— 这是给「个人端内嵌本机库」这种形态用的。

## 七、日常运维

**每日备份**（SQLite 含 WAL，务必定时）：
```bash
crontab -e
# 加一行（每天 03:00 备份，保留最近 30 份）：
0 3 * * * /root/starmap/tools/deploy/backup.sh /root/starmap
```
备份文件在 `backups/`，恢复 = 用备份 .db 替换 `server/data/starmap.db` 再 `pm2 restart starmap`。

**更新版本**：服务器上 `bash tools/deploy/deploy.sh`（自动 pull+build+import+restart）。

**挂管理 AI 桥**（投稿/审核/举报/勘误全自动）：
1. 服务器装 Ollama（`curl -fsSL https://ollama.com/install.sh | sh`）并拉一个模型 `ollama pull qwen2.5`；或配云 API key。
2. 复制配置：`cp tools/management-ai/config.example.json tools/management-ai/config.json`，填 `baseUrl`(http://localhost:3000)、`username/password`(你的管理员账号)、`model`、`api`、`key`。
3. `npm run management-ai`（或在 PM2 里常驻，加一条 `pm2 start npm --name management-ai -- run management-ai`）。

## 八、常见问题

- **忘设 STARMAP_SECRET**：已用默认 dev-secret，风险高——改 `export STARMAP_SECRET=...` 后 `pm2 restart starmap`。
- **端口 3000 被占**：`PORT` 环境变量改端口，Nginx 对应改 `proxy_pass`。
- **白屏/资源 404**：多半是没 `npm run build` 或没在仓库根目录启动（静态目录是 `web/dist`）。公网根路径返回"说明页"而不是学习界面，是**设计如此**，不是报错。
- **进不了管理界面**：先在本机（服务器上）登录 `https://你的域名/admin` 并点「认领为库管理员」（仅本机请求可认领），或用 `create-admin.mjs` 建管理员账号。
- **数据库被误删**：用 `backups/` 里的备份恢复即可。
