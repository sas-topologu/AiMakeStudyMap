# 知识卡制作规范

> 版本 v2.1（递进主线+节内教学版）。本规范是智点星谱内容生产的唯一标准。AI 制卡与人类供稿均须遵守；不符合本规范的卡片无法通过导入校验入库。zod schema（`content/schema/knowledge-card.schema.js`）为字段的最终裁决。
> v2.1 相对 v2.0 的变化：①正文 sections 按**认知递进主线**组织（禁止并列堆砌）；②例题与易错点**跟随所属知识点**（节内 `examples`/`pitfalls`）；③新增节内**工具表**（`tools`，如积分表/求导表）；④推导类内容必须给出完整推理链。

## 1. 基本概念

- **节点**：一个知识单元。前端是星图中的一颗星，后端是以一个概念为核心的知识卡。
- **知识卡**：一个 JSON 文件描述一个节点，一卡一文件，存放于 `content/cards/`。
- **连线**：由卡中标注的关联关系生成，分前置、后续、相关三种。后续关系由其他节点的前置关系反向推导，不单独标注。
- 节点数据库性质：静态、高可靠、版本化。一切内容变更经审核后通过导入工具入库并迭代版本号。

## 2. 内容定位与取材标准

0. **推演式制作（最高原则）**：本程序的主要功能是辅助学习。**基础内容（中小学及大学本科的全部知识）必须以「推演」制作**——模仿知识的诞生过程，从更基础的知识一步步推演而来；**禁止构建式、词条式制作**（堆砌「定义-性质-例题」清单）。每张基础卡应当回答：这个概念是为解决什么问题而诞生的？前人如何从已有知识出发把它推出来？推演链由浅入深、不跳步，读者顺着读等于重走一遍知识的发现之路。
1. **一卡 = 一节课**：每张知识卡的内容体量对标教科书的**一个小章节（一节课的内容）**——不大于一章、不小于一个知识点。
2. **对标教材**：自然科学卡依据经典教科书体系生成；内容组织参照教材章节的完整构成（见 §4）。
3. **前沿领域替代取材**：前沿领域没有教科书、不存在对应参考时，**可以使用论文替代**作为内容来源；引用论文须在内容中客观陈述，涉及未定论结论时 `credibility` 标 `disputed`。
4. **内容完整性优先于篇幅控制**：宁可卡长，不可缺环。一节课该有的部分不许为凑短而砍掉；体量过大时应当拆成多张卡并建立前置/相关关系，而不是删内容。

## 3. 文件与字段规范

卡片文件名建议与 id 末段一致，如 `math.equation.quadratic.json`。※ = v2.0 新增。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 点分层级唯一 id，正则 `^[a-z][a-z0-9]*(\.[a-z0-9-]+)+$`，建议 `学科.领域.概念` |
| `title` | string | 是 | 节点中文标题 |
| `subject` | string | 是 | 学科（宏观视图的"星系"） |
| `category` | enum | 是 | `自然科学` / `人文科学` |
| `credibility` | enum | 是 | `verified`（绿）/ `disputed`（黄，存在争议或论文未定论） |
| `difficulty` | int 1~5 | 是 | 难度，影响考核题数与低难路径 |
| `summary` | string | 是 | 一段话摘要 |
| `objectives` ※ | string[] | 建议 | 学习目标：学完本卡能做什么，3~5 条 |
| `sections` | array | 是 | 正文，见 §4.2；每项 `{heading, body, tier, examples?, pitfalls?, tools?}`（子字段见 §4.4） |
| `terms` | object | 是 | 术语表，对应悬浮定义夹层 |
| `media` ※ | array | 可选 | 图片/动画，见 §5 |
| `examples` ※ | array | 建议 | 例题（分步详解），见 §6 |
| `pitfalls` ※ | string[] | 建议 | 易错点/常见误区，2~4 条 |
| `emblems` ※ | array | 建议 | 核心标注（星图粒子拼形素材），见 §7 |
| `relations` | object | 是 | `{"prerequisites": [id...], "related": [id...]}` |
| `questionBank` | array | 是 | 闯关题库，每节点 ≥6 题，见 §8 |
| `version` | int | 是 | 卡片版本，修改 +1 |

## 4. 正文：教材章节构成与折叠分级

### 4.1 一节课的递进主线（照此组织卡片）

知识卡内容必须沿**认知递进主线**组织，而不是并列罗列知识点：

1. **学习目标**（`objectives`）
2. **正文讲解**（`sections`，3~6 节，递进主线）：问题引入 → 定义/原理 → 推导论证 → 工具/技巧 → 应用 → 小结
3. **图示/动画演示**（`media`）
4. **例题与易错点**：默认**内嵌在各知识点节后**（见 §4.4），与正文同屏衔接
5. **习题**（`questionBank`，考核用，见 §8）

- 相邻节之间应体现递进：后一节建立在前一节结论之上（如「面积问题 → 定积分定义 → 基本定理 → 技巧 → 应用」），而不是互不依赖的并列主题。
- 节数 3~6：太少说明拆分不足，太多（>6）通常是并列堆砌或粒度失控——多而不精时应合并或拆分多卡。

### 4.2 sections 折叠分级（`tier`）

教材内容体量差异大、用户水平不同（已掌握者要速览笔记，未学者要完整教材），每节必须标注折叠级别 `tier`：

| tier | 适用内容 | 速览模式 | 标准模式 | 完整模式 |
|---|---|---|---|---|
| `core`（默认） | 概念、定义、定理、应用、小结等主干 | 列标题，可点展开 | 展开 | 展开 |
| `detail` | 公式推导、定理证明、详细论证 | 隐藏 | 折叠，可点展开 | 展开 |
| `extended` | 拓展阅读、超纲延伸、前沿链接 | 隐藏 | 折叠，可点展开 | 展开 |

标注原则：**不依赖推导也能学会用法的，推导标 detail**；学有余力才需要的，标 extended；其余一律 core。速览模式下应能让已掌握者 1 分钟过完本卡要点。

### 4.3 术语标注（夹层系统）

- 正文、例题、术语定义中的专业名词/参数/算子一律 `[[术语]]` 标注。
- sections 中出现的每个 `[[术语]]` 必须在本卡 `terms` 中有定义（导入校验强制）；定义文本可继续 `[[...]]` 嵌套引用，禁止循环定义。
- 跨卡概念不硬标，通过 `related` 建立连接。

### 4.4 节内例题、易错点与工具表（v2.1）

例题与易错点**紧跟所属知识点**，内嵌在 `sections` 对应节内：

```json
{
  "heading": "原函数与不定积分",
  "tier": "core",
  "body": "…",
  "tools": {
    "heading": "基本积分公式表",
    "rows": ["∫xⁿdx = xⁿ⁺¹/(n+1)+C（n≠-1）", "∫cos x dx = sin x+C", "∫eˣdx = eˣ+C"]
  },
  "examples": [
    {"id": "ex-a", "title": "…", "problem": "…", "steps": ["…"], "answer": "…"}
  ],
  "pitfalls": ["忘记加常数 C：…"]
}
```

- `examples`：本节专属例题，结构同 §6；`pitfalls`：本节专属易错点。二者渲染在本节正文之后。
- `tools`：工具表（公式表/口诀/对照表），`heading` + `rows`（每行一条，可用数学记号）。数学、物理等有公式表的学科**强烈建议**提供。
- 顶级 `examples`/`pitfalls` 字段保留：仅用于综合全卡内容、无法归属单节的例题与易错点；不得把所有例题都堆在顶级（旧卡已堆的暂兼容，新卡/重做卡必须按节归属）。

### 4.5 推理过程（v2.1）

- **推演链是卡片的骨架**：基础卡从「更基础的知识」出发推演出本卡结论，正文呈现完整的诞生过程：
  1. **动机问题**：这个概念为解决什么问题而生？（如「怎样求曲边图形的面积？」催生定积分）
  2. **推演步骤**：从已有基础出发，一步一步导出结论；每一步只允许一步标准运算/推理，并写明依据（用哪个已知结论）
  3. **结论定型**：给出最终定义/定理的精确表述
  4. **应用**：结论能解决什么，回到动机问题
- 每个结论公式必须有来路：能推导的给完整推导链；经验性的标「经验/实验规律」并说明适用条件。
- 推导细节可标 `detail` 节，但**动机与推演主干必须留在 core**（速览者也要看到知识的来龙去脉）。
- 工具表（§4.4）中的公式条目，首次出现时应在正文或 detail 节给出推导或来源说明。

### 4.6 排版整洁（v2.1）

- 正文段落 **2~4 句**，段落之间用空行分隔；禁止一整节一长段。
- **公式一式一行**：公式必须独占一行（前后空行），不嵌在叙述句中；前端会自动把公式行居中显示。
- 叙述与公式分离：公式行内只放数学记号（可带简短括注），理由与说明写在正文句。
- 推导链每一步一条，列表式呈现推导步骤。

## 5. 图片与动画（`media`）

```json
{"id": "parabola-roots", "type": "image", "src": "quadratic/parabola-roots.svg", "caption": "抛物线与 x 轴交点即方程的根", "core": true}
```

- `type`：`image`（静态图）/ `animation`（动画演示）。
- `src`：http(s) URL，或相对 `content/assets/` 的路径（如 `quadratic/parabola-roots.svg`）。本地文件按 `节点id首段/文件名` 组织目录；**导入时校验文件存在**。
- 格式：**首选 SVG**（矢量、小体积、AI 可生成；SVG 内嵌 SMIL 即为动画）；位图允许 png/jpg/webp，动图允许 gif。
- 图注 `caption` 必填（前端展示）。
- `core: true` 标注"最能代表本卡的一张图"（作卡片头图），每卡至多 1 个。
- 图片必须深色背景友好（应用为深色星空主题）：透明底、浅色线条文字。

## 6. 例题（`examples`）

```json
{"id": "ex1", "title": "公式法解方程", "problem": "用求根公式解 x²-5x+6=0",
 "steps": ["a=1，b=-5，c=6", "Δ=25-24=1>0", "x=(5±1)/2"], "answer": "x₁=2，x₂=3"}
```

- 例题是**教学演示**，与闯关题库（§8）**分离**，不得互相抄用（防止泄露考核答案）。
- `steps` 必须分步、每步一句；`answer` 单独给出（前端默认折叠防剧透）。
- problem/steps 可用 Markdown 与 `[[术语]]`。
- 每卡建议 2~4 道，覆盖本卡核心考法；**v2.1 起例题默认内嵌在所属节（§4.4）**。

## 7. 核心标注（`emblems`，星图粒子素材）

星图中心视图会用星光粒子围绕当前节点拼出本卡最核心的公式或图片（组成→消散→循环），素材来自制卡时标注的 `emblems`：

```json
{"emblems": [
  {"type": "formula", "content": "x=(-b±√(b²-4ac))/(2a)", "caption": "求根公式"},
  {"type": "image", "content": "parabola-roots", "caption": "抛物线与根"}
]}
```

- 每卡标注 **1~3 个**，选取标准：**最有代表性、一眼认出本卡**的公式或图。
- `type: formula`：content 为公式文本（纯文本数学记号，单行为宜，过长会缩得过小）。
- `type: image`：content 为本卡 `media` 中某个图形的 **id**（导入校验强制）；图形应线条简洁（粒子是点阵拼形，过密的图效果差）。
- `caption` 会在粒子驻留时显示，写短名称。

## 8. 闯关题库（`questionBank`）

```json
{"id": "q1", "type": "choice", "stem": "…", "options": ["…"], "answer": 1, "explanation": "…", "difficulty": 2}
```

- `choice`：单选，`answer` 为正确选项下标（从 0 开始）；`fill`：填空，`answer` 为标准答案字符串（去首尾空白精确比对，**题干必须保证答案唯一**，精度要求写清）。
- 每题必须有 `explanation`。
- 每节点 **≥6 题**、难度有梯度；考核抽题数 = `min(clamp(22-4×难度,4,20), 题库容量)`，**低难度节点题库建议 ≥20 题**；通关固定抽 3 题且全对，需保证至少 3 道中低难度题。
- **自洽性**：题目必须能从本卡正文及前置链知识解答，不得超纲；通关目标时耗 ≤40 分钟。

## 9. 关联关系标注规则

- **prerequisites（前置）**：学习本节点必须已掌握的**直接**前置节点，只标直接前置；前置关系构成 DAG，**严禁循环依赖**（导入强制中止）。
- **related（相关）**：触类旁通的节点（可跨学科），无向，单方标注即可。
- 引用的 id 必须存在；新卡必须接入主网络，禁止孤岛。

## 10. 制作与入库流程

```
制卡（AI/人）→ content/staging/ → 校验 → 审核 → 移入 content/cards/ → npm run import
```

```bash
# 校验（不写库，主库节点纳入图校验）
node content/tools/import.js --dir content/staging --check --with-db server/data/starmap.db
# 入库（幂等；有变化自动 content_version+1 并写更新日志）
npm run import
```

修改已有卡时卡内 `version` +1。删除节点见《维护手册》§5。

## 11. 审核 checklist

- [ ] **推演式制作（最高原则）**：动机问题 → 从更基础知识推演 → 结论 → 应用；无词条式堆砌（定义-性质清单）
- [ ] 体量对标一节课；内容完整（§4.1 递进主线齐全或说明缺省理由），**完整性未被篇幅让路**
- [ ] sections 3~6 节、沿认知递进主线组织（非并列堆砌）；多而不精时合并或拆卡
- [ ] 教材级准确；前沿内容取自论文且争议处标 `disputed`
- [ ] objectives 3~5 条、可检验
- [ ] 每节 tier 标注恰当（速览 1 分钟能过完要点）
- [ ] 例题/易错点内嵌在所属节后；仅综合题留在顶级；与题库无重复
- [ ] 有公式表的学科提供节内 `tools`；公式首现处有推导或来源（§4.5）
- [ ] 推导不跳步、每步有依据
- [ ] 术语 `[[...]]` 全部有定义（含节内例题/易错/工具表）、无循环；跨卡概念走 related
- [ ] media 深色友好、有图注；SVG 首选；core 图至多 1 个；本地文件存在于 content/assets/
- [ ] 例题分步详解、与题库无重复；answer 正确
- [ ] emblems 1~3 个、确有代表性；image 型引用本卡 media id
- [ ] 题库量与梯度达标、自洽、fill 答案唯一
- [ ] 前置为直接前置、无环、接入主网络
- [ ] `--check --with-db` 通过

**范例卡**：`content/cards/math.equation.quadratic.json`（全字段标杆，含 SVG 图与 emblems）。
**v2.1 递进主线+节内教学范例**：`content/cards/math.calculus.integral.json`（节内 tools/examples/pitfalls 标杆）。
